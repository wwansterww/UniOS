# UniOS — расписание, дедлайны и объявления Нархоза в одном месте

MVP веб-приложения для студентов и преподавателей Университета Нархоз (Алматы).
Студент находит ближайший дедлайн за 30 секунд и вовремя получает напоминание в Telegram.

- **Оценки по правилам Нархоза:** работы делятся на РК1, РК2 и Экзамен; итог = 60% рейтинга допуска (среднее РК1 и РК2) + 40% экзамена; допуск к экзамену — от 50. GPA по шкале A = 4.0 … F = 0 с весом по кредитам, за семестр и общий; история прошлых семестров.
- **Лимит НБ 25%:** число пар считается по расписанию (30 пар → 7 пропусков), опоздания и уважительные пропуски в лимит не входят.
- **Студент:** «Сегодня» (следующая пара с обратным отсчётом, дедлайны на 7 дней с цветными метками, изменения), расписание (сетка на десктопе / список на телефоне), дедлайны с фильтрами и кнопкой «Сделано», **оценки** (РК1/РК2/Экзамен, «сколько нужно на экзамене» для каждой буквы, комментарии преподавателя, режим «Что если?», история GPA), **посещаемость** с лимитом НБ 25% («можно пропустить ещё N пар»), **справки** (фото или PDF к пропуску, статус проверки), **отметка по QR-коду** или 6-значному коду, личные задачи, объявления с «прочитано», окна регистрации на дисциплины, поиск `Ctrl+K` / `/`, настройки уведомлений, Telegram, `.ics`-календарь, импорт из Canvas.
- **Преподаватель:** **посещаемость** (QR-код на проектор — студенты отмечаются сами, код меняется каждые 15 секунд; «Все на месте» и отметка одним нажатием; «НБ 6/7» у каждого; сводка по группе, «Близко к лимиту» и кнопка «Предупредить»; справки: принять / отклонить; выгрузка в Excel), **журнал оценок** (РК1/РК2/Экзамен, ввод прямо в ячейку, комментарии к оценке, аналитика распределения, импорт из Excel и CSV-экспорта Canvas, выгрузка в Excel), кредиты курса для GPA, курсы и группы с кодами приглашения, «новый дедлайн за 10 секунд», расписание (повтор по неделям, CSV, перенос / отмена / смена аудитории), объявления (важные, закреплённые), «прочитали 18 из 25» + «Напомнить им», метрики MVP.
- **Движок напоминаний:** 2 суток / 24 ч / 1 ч (любая комбинация, по умолчанию 24 ч + 1 ч), «Срочно», тихие часы, утренний дайджест, мгновенные сообщения об изменениях, повторы при ошибках.

## Быстрый старт (локально, без настройки)

```bash
npm install
```

```bash
npm run dev
```

Откройте http://localhost:3000 и войдите почтой и паролем.

### Аккаунты

Аккаунты выдаёт университет: в системе **5 преподавателей, 10 студентов (ИС-23-1 и ФИН-23-2) и 1 эдвайзер**.
Новые преподаватели, в том числе не из Нархоза, подают заявку сами — см. «Заявки преподавателей» ниже.
Список — в `lib/db/accounts.ts`. Пароли у каждого свои: они создаются при первом заполнении базы в `accounts.local.json`,
а таблица «роль — имя — почта — пароль» для раздачи — в **`ACCOUNTS.local.md`**. Оба файла не попадают в git;
`npm run db:reset` пароли не меняет. Чтобы выдать новый пароль, удалите строку человека из `accounts.local.json` и пересоздайте базу.

**Безопасность и управление.** Эдвайзер в разделе «Аккаунты» добавляет людей, сбрасывает пароли (временный пароль
показывается один раз, после входа UniOS просит придумать свой), блокирует и переводит студентов между группами.
Каждый может сменить пароль в профиле и выйти на всех других устройствах. После 5 неверных паролей почта блокируется
на 15 минут (адрес, который перебирает много почт, — после 20); заблокированный аккаунт войти не может.

**Заявки преподавателей.** На странице входа — ссылка «Подать заявку» (`/register`): имя, почта, пароль,
предметы и занятия по дням недели (пары Нархоза по 75 минут, группа, аудитория) и период. Заявка приходит эдвайзеру
в «Заявки» (и в Telegram). Он видит, где она пересекается с расписанием: у группы в это время другая пара или аудитория
занята. «Принять» в одной транзакции создаёт аккаунт с паролем, который выбрал преподаватель, курсы и все занятия
периода; «Отклонить» — с причиной. Пока решения нет, вход с этой почтой и паролем показывает статус заявки — и только
её автору. Защита публичной формы: не больше 5 заявок в час с адреса, 3 в сутки на почту, 100 открытых всего,
скрытое поле против ботов; таблица `teacher_applications` недоступна роли `uni_app` (в ней хеши паролей).

Без `DATABASE_URL` приложение запускает встроенный Postgres (PGlite) в папке `.data/` и само заполняет его этими аккаунтами
и семестром относительно текущего времени: 5 предметов, расписание на 15 недель, оценки, посещаемость, дедлайны, объявления, справки и два прошлых семестра.

Перед защитой пересоздайте базу, чтобы даты были «свежими»:

```bash
npm run db:reset
```

На опубликованном сайте (Supabase) то же самое делает `demo:reset`: семестр собирается заново вокруг сегодняшнего дня,
а аккаунты сохраняют пароли (и сменённые тоже), привязку Telegram, язык, настройки напоминаний и реальную статистику
из `/metrics`. Без `--yes` команда только показывает, какую базу затронет:

```bash
npm run demo:reset -- --yes
```

Сценарий показа на защите — в [docs/DEMO.md](docs/DEMO.md).

### Отметка по QR-коду с телефонов на защите

QR-код ведёт на адрес, с которого преподаватель открыл сайт. `localhost` с телефона не откроется, поэтому для демонстрации
в одной Wi-Fi-сети запустите сервер так и откройте сайт на ноутбуке по IP (например `http://192.168.1.5:3000`):

```bash
npm run dev -- -H 0.0.0.0
```

После публикации на Vercel это не нужно: QR ведёт на настоящий адрес сайта. Без камеры студент вводит 6 цифр на странице «Отметиться».

| Часть | Как сделано |
| --- | --- |
| Фронтенд | Next.js 16 (App Router, Server Components, Server Actions), TypeScript, Tailwind CSS 4, компоненты в стиле shadcn/ui (`components/ui.tsx`), lucide-иконки, sonner-тосты |
| База | Postgres. Локально — PGlite (тот же Postgres 17 в WebAssembly), в проде — Supabase Postgres через `DATABASE_URL` |
| Схема и RLS | `lib/db/migrations.ts` (то же самое в `supabase/migrations/*.sql`) |
| Доступ к данным | Все чтения от имени пользователя идут через `withUser()` → `set local role uni_app` + `app.user_id`, поэтому **RLS реально применяется**. Роль `uni_app` умеет только `SELECT`; запись — через серверные действия с явной проверкой владельца курса |
| Вход | Почта + пароль; ссылка для входа по почте — если настроен Resend. Аккаунты из `lib/db/accounts.ts`; преподаватели подают заявку на `/register`, эдвайзер принимает её (`lib/applications.ts`) |
| Напоминания | `lib/reminders/plan.ts` (чистая логика) → `engine.ts` (пересчёт таблицы `reminders`) → `dispatch.ts` (отправка) |
| Планировщик | `/api/cron/tick`: pg_cron в Supabase вызывает его каждые 5 минут; локально `instrumentation-node.ts` тикает каждую минуту |
| Telegram | `lib/telegram/bot.ts`: `/start <токен>`, `/today`, `/week`, `/deadlines`, кнопки «✅ Сделано», «⏰ Через 1 час», «Открыть в UniOS». Локально — long polling, в проде — webhook |
| Реальное время | Открытые страницы опрашивают `/api/version` (раз в 10 с и при фокусе) и перерисовываются, когда что-то поменялось |
| PWA | `app/manifest.ts`, `public/sw.js`: установка на главный экран, «Сегодня» и расписание доступны офлайн |
| Локализация | `lib/i18n/{ru,kk,en}.ts`, переключатель RU / ҚАЗ / EN. Время хранится в UTC, показывается в Asia/Almaty |

### Движок напоминаний

1. При создании / изменении дедлайна, смене настроек студента или вступлении в группу пересчитывается таблица `reminders`:
   на каждую тройку «студент × дедлайн × интервал» — время `send_at`. Уникальный ключ `(student_id, deadline_id, offset_minutes)`.
2. Прошедшие интервалы пропускаются. Если до срока меньше самого короткого интервала — одно сообщение «Срочно» сразу.
3. Тихие часы (по умолчанию 23:00–08:00): напоминание переносится на 08:00; если сам дедлайн раньше 08:00 — отправляется до начала тихих часов (22:45).
4. Каждый тик берёт `send_at <= now() and sent_at is null` с `FOR UPDATE SKIP LOCKED`, отправляет и пишет `sent_at`. При ошибке — до 3 попыток, всё логируется в `events`.
5. «Сделано» (на сайте или в Telegram) удаляет будущие напоминания; диспетчер дополнительно пропускает сделанные и удалённые дедлайны.
6. Перенос дедлайна сбрасывает расписание напоминаний и сразу отправляет «Дедлайн перенесён: ~~пт 18:00~~ → пн 12:00».

Критерии приёмки покрыты тестами (`tests/plan.test.ts`, `tests/engine.test.ts`):
дедлайн, созданный в 10:00 на завтра 18:00 → сообщения сегодня в 18:00 и завтра в 17:00; 02:00 → 08:00; за 30 минут → одно «Срочно».

## Деплой: Supabase + Telegram + Vercel

### 1. Supabase

1. Создайте проект на https://supabase.com. Регион функций Vercel в `vercel.json` должен совпадать с регионом базы
   (сейчас `bom1` — Мумбаи, база в `ap-south-1`; для Frankfurt `eu-central-1` → `fra1`): каждый запрос к странице — несколько запросов к базе.
2. Кнопка **Connect → Direct → Transaction pooler** (Shared pooler, порт 6543). Скопируйте строку — это `DATABASE_URL` — и вставьте в файл `.env.supabase`
   (он не попадает в git; локальный сервер его не читает и остаётся на своей базе).
3. Примените схему, RLS и заполните базу аккаунтами — с вашего компьютера (пароли возьмутся из вашего `accounts.local.json`):

   ```bash
   npm run db:migrate
   ```

   Без заполнения: `SEED_DEMO=false npm run db:migrate`. Сам сайт на Vercel базу не заполняет — только этой командой.

### 2. Telegram-бот

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot` → придумайте имя и username (например `unios_narxoz_bot`).
2. Скопируйте токен → `TELEGRAM_BOT_TOKEN`, username без `@` → `TELEGRAM_BOT_USERNAME`.
3. Локально этого достаточно: при `npm run dev` бот работает через long polling. Профиль → «Подключить Telegram» → «Start».
4. Меню команд и описание бота в Telegram: `npm run telegram:setup`.

Что умеет бот: постоянное меню (📅 Сегодня, ⏭ Следующая пара, 📌 Дедлайны, 🗓 Неделя, ⚙️ Напоминания),
кнопки «✅ Сделано» и «⏰ Через 1 час» в напоминаниях, настройка «за 2 суток / 24 ч / 1 ч / все сразу»,
утренний дайджест и мгновенные сообщения о переносах — прямо в чате.

### 3. Vercel

1. Залейте репозиторий на GitHub и импортируйте его на https://vercel.com/new.
2. В **Settings → Environment Variables** заполните (см. `.env.example`):

   | Переменная | Значение |
   | --- | --- |
   | `APP_URL` | `https://<ваш-проект>.vercel.app` |
   | `DATABASE_URL` | строка из Supabase (pooler, 6543) |
   | `AUTH_SECRET` | `openssl rand -base64 32` |
   | `DEMO_MODE` | `false` |
   | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` | из BotFather |
   | `TELEGRAM_MODE` | `webhook` |
   | `TELEGRAM_WEBHOOK_SECRET` | любая случайная строка |
   | `CRON_SECRET` | любая случайная строка |
   | `RESEND_API_KEY`, `EMAIL_FROM` | по желанию (запасной канал email и magic link) |

3. Deploy. Затем подключите вебхук бота (с этими же переменными в `.env.local`):

   ```bash
   npm run telegram:webhook
   ```

4. Включите планировщик: откройте `supabase/cron.sql`, подставьте `APP_URL` и `CRON_SECRET` и выполните в Supabase SQL Editor.
   Проверка: `select * from cron.job_run_details order by start_time desc limit 5;`

Секреты (`DATABASE_URL`, токены) используются только на сервере и никогда не попадают в браузер.

## Метрики MVP

`/metrics` (для преподавателей и команды) считает по таблице `events`:
время от открытия приложения до открытия дедлайна (медиана, цель ≤ 30 с), долю студентов с Telegram и включёнными
напоминаниями, сколько напоминаний отправлено и открыто (ссылка «Открыть в UniOS» ведёт через `/r/<id>`),
долю дедлайнов, отмеченных «Сделано» до срока. Часть замеров `deadline_open` в демо-базе — сид (`props.seed = true`).

## Структура

```
app/
  login/                 вход (почта + пароль), ссылка по почте
  (app)/today|schedule|deadlines|announcements|registration|profile|notifications   — студент
  (app)/teacher/...      — преподаватель; (app)/metrics — метрики
  api/cron/tick          — планировщик;  api/telegram/webhook — бот
  api/ics/[token]        — личный календарь .ics;  r/[id] — открытие напоминания
lib/
  db/                    адаптер Postgres/PGlite, миграции, сид
  reminders/             plan.ts (логика) · engine.ts (пересчёт) · dispatch.ts (отправка)
  telegram/  notifications/  canvas.ts  ics.ts  jobs.ts  queries.ts  time.ts  i18n/
supabase/                migrations/*.sql, cron.sql
tests/                   vitest
```

## Не входит в MVP

Настоящая регистрация на дисциплины, интеграция с Platonus, нативные приложения, оплата, чаты между пользователями.
Следующие шаги: ИИ-разбор сообщений из WhatsApp/Telegram в дедлайны, браузерные push-уведомления через PWA.
